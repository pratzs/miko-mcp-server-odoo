Connect Claude, ChatGPT or Copilot to Odoo, without handing over the keys.

An assistant that can answer "what did we invoice this customer last quarter" is genuinely useful. An assistant with unrestricted read access to your ERP is a problem nobody senior will sign off. This is built so it can be signed off.

Nothing is exposed when you install it. No model is readable until an administrator lists it. Writing is off unless you turn it on, per model, and again per key. Named fields can be stripped so salaries and bank details never leave. And every question the assistant asks is written to an audit log with the key that asked it.

You can see exactly what it asked, and what you refused

Real calls against a real database. Note the refusals: an attempt to read a model that is not on the allowlist is recorded, not silently dropped.

This is the part that matters at audit time. "We connected an AI to the ERP" is an unanswerable question without it.

You decide what it can see

ControlWhat it does
AllowlistA model the assistant cannot see does not exist as far as it is concerned. Empty by default.
Read onlyWriting is off per model and per key. Both have to be on before anything changes.
Redacted fieldsNamed fields are stripped from every response. Passwords, tokens and API keys are always stripped, whatever you configure.
Restrict toAn Odoo domain the assistant can never see past. One company, or this year only.
Row ceilingA cap on how much one question can pull.
Acts as a userEvery request runs as a real Odoo user, so record rules and access rights still apply. A key can never reach further than the person behind it.

The allowlist can only ever narrow what that user could already reach. It can never widen it.

What the assistant can do

odoo_list_modelsWhich models it is allowed to read, and what it may do with each.
odoo_describe_modelThe fields of an allowed model, so it can write a correct query instead of guessing.
odoo_searchSearch and read, using standard Odoo domain syntax.
odoo_countCount without pulling the records.

Standard Model Context Protocol over JSON-RPC at /mcp, so any MCP client works. Authenticate with Authorization: Bearer <key>.

Setting it up

  • Install, then open MCP Server > Allowed Models and add the models the assistant should see. Until you do, it can read nothing.
  • Create a key under Keys. It is shown once and stored hashed, so it cannot be read back out of a backup.
  • Point your MCP client at https://your-odoo/mcp with that key.
  • Watch Audit Log to see exactly what it does with the access.

Keys are stored as a SHA-256 digest. The audit log is written on its own transaction, so a refused or failed request still leaves a record.
